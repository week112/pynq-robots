# 03 把日志原样贴给模型,让它先分类再下结论

**提示词模板**

```
下面是 <Vivado/Vitis HLS/Jupyter> 的原始输出(未删减)。请:
1. 把每条 WARNING/ERROR 分为"可忽略/需处理/不确定",各给一句理由;
2. 对"需处理"的给出最小验证步骤(一条命令或一个实验),先不要改代码;
3. 如果我给的信息不足以下结论,明确列出还缺什么数据。
<粘贴日志>
```

- **适用场景**:综合/实现告警、板上异常、程序行为与预期不符。
- **已验证效果**:本队用于排查开发板掉线:模型先后提出供电、摄像头等假设,每个假设对应一个可做的对照实验;开发者逐项试过后发现"每次运行前重启内核就不掉线",才定位到根因。要点是**让模型提出可检验的实验,而不是直接下结论**——前两个假设(换电源、给摄像头单独供电)试过后都没能根治。
- **失效条件**:日志被截断或只贴报错一行时,模型容易猜错。
- **来源**:见 `../pitfalls.md` 第 1 条。
