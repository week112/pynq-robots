# 01 软硬件划分:让大模型先问"该不该上 FPGA"

**提示词模板**

```
我的系统:<一句话描述>。已知指标:<延迟/吞吐/功耗要求>。器件:<型号与资源>。
请先不要写代码。按下面顺序回答:
1. 列出所有处理环节及各自的估计耗时(给出依据,不确定的标明"待测")。
2. 哪些环节必须确定性(硬实时/看门狗/微秒时间戳)?这些放 PL 的理由是什么?
3. 哪些环节放 PL 收益不大?给出"不上 PL"的理由。
4. 给出最小的实测方案,用来在动手前验证你的判断(基线测量清单)。
```

- **适用场景**:选题与划分阶段;任何"感知—决策—执行"类嵌入式系统。
- **已验证效果**:本队的实际做法是先在板上测基线(ARM 预处理 P50 13.0 ms;PS→PL 写 P50 23.7 µs、P99.9 233 µs),再决定把电机 PWM、看门狗、IMU 采样与时间戳放进 PL,YOLO 推理留在 PC。对图像预处理核的取舍也如实写进了报告:它加速 4.0×(核本身),但摄像头输出 JPEG,当前主控制环没有用到它。
- **失效条件**:模型给出的耗时是估计,必须用基线实测替换;不要把"想用 FPGA"当作理由。
- **来源**:早期方案阶段的划分讨论(模板是对当时做法的提炼,不是逐字复用的提示词)。
