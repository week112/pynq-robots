# 踩坑清单

格式:现象 → 触发条件 → 排查步骤 → 处理 → 本队是否验证。

1. **开发板"掉线",ping 不通,断电重启才好**
   - 触发:在同一 Jupyter 内核里重复运行含 `Overlay("x.bit")` 的单元,而旧的心跳线程仍在访问 AXI。
   - 排查:先排除供电(换电源/摄像头单独供电均未解决),再做对照——"每次运行前重启内核"是否就不掉线。
   - 处理:同一比特流只加载一次(`skill/pynq_safe_overlay`);重建对象前先关旧线程并释放摄像头。
   - 验证:实板上重复运行不再掉线(未做长时统计)。

2. **IMU(I²C)读数恒为 0,拔掉传感器也没有 NACK**
   - 触发:块设计把含 `inout` 的 RTL 模块当作独立单元,三态信号没有映射到物理引脚;仿真看不出来。
   - 排查:读 `raw_sel=6` 看 SCL/SDA 引脚电平;WHO_AM_I 应为 0x70(本队 GY-521 实测)。
   - 处理:在 RTL 里显式例化 `IOBUF`。
   - 验证:实板恢复正常。

3. **电机低占空比只嗡鸣不转**(TT 电机 + 塑料轮)
   - 处理:PL 内加死区补偿 `min_duty`;转向改用"满功率短脉冲 + 读角"的闭环(约 120 ms ≈ 20°)。
   - 验证:转向误差中位数 1.77°,21/23 次 ≤3°;2 次大偏差(15.4°、28.1°)出现在椅子离得很近、首帧就触发的试验。

4. **视觉判据 `ybot` 恒为 1.0**
   - 触发:摄像头装得低,物体底边落在画面底部。
   - 处理:改用检测框面积占比做触发,并按类别设阈值(小物体 0.06、大物体 0.10)。
   - 验证:水瓶约 0.65~0.7 m 触发。

5. **`can't open camera`**
   - 触发:USB 摄像头供电不足,或(可能)被旧进程占用。
   - 排查:`!ls /dev/video*`;关闭旧的 Vision 对象后重试;给摄像头单独供电不一定有效(本队实测不是根因)。

6. **服务端没有输出、没有 `latest.jpg`**
   - 触发:运行的是旧版 `server_v2.py`。处理:覆盖为新版,确认文件里有 `latest.jpg` 字样后重启服务。

7. **电机突然不转 / 转一下就停**
   - 触发:电机电池盒接触松动。处理:用胶带固定。

8. **改了 `car_pl.py` 没有效果**
   - 触发:Jupyter 缓存了旧模块。处理:菜单 Kernel → Restart 再运行(这也同时规避第 1 条)。

附:Vivado 更新 `imu_reader` 模块引用时出现 `HDL port or parameter 'qtick' has a dependency on ... 'QDIV'` 的警告,本队工程中最终综合、实现通过,时序满足,未观察到由它引起的功能问题;我们将其归为"可忽略",但没有单独验证。
